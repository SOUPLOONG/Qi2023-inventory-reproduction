# 数据来源、形状与字段

所有生成面板均在路径及provenance中标记SYNTHETIC。数据许可：本工程生成的合成数据可以用于学习与复现；作者原始披露CSV保留原作者权利和使用条件，未增加开放授权。未随包转发论文PDF。

## 合成生成过程

2,000个商品—仓库序列，420天，6个合成类别、4个仓库。每个序列有独立基准需求、周期相位、波幅、趋势、供应商可靠度及5—10天review。需求为含周周期、90天周期、促销和趋势的Gamma-Poisson计数；促销概率0.12、幅度0.8；Gamma形状10。基准lognormal(2.4,0.65)，趋势范围−0.0005..0.001；供应可靠度Uniform(.15,.85)，提前期=1+Binomial(3,p)。生成器的参数来自本工程，不是从JD数据估计。

`panel.npz`：demand[N,420]，promo[N,420]，lead[N,420]，review[N]，scale[N]，static[N,12]，category/warehouse[N]。
`daily_panel.csv.gz`：series_id、day（零起点）、demand（日需求）、planned_promotion（事先已知）。
`potential_orders.csv.gz`：例示按各商品review生成的潜在下单日、实际提前期、实际到货日。模拟器可能在不同anchor上定义同样间隔的订货日，因此完整实际lead以panel为准，实际执行订单以results/decisions为准。

每日lead是潜在供应商报价/完成记录，用于定义任意候选下单日的外生实现，不由策略或数量改变。它不是预测时可见的未来报价。订单数量没有供应容量约束、采购费或固定下单费，符合此简化库存目标的边界。

## 132维快照：明确的新定义

|特征|维数|处理|
|---|---:|---|
|过去28天需求/scale、促销、周内正弦|84|只用截至t−1的信息|
|6类别one-hot+4仓库one-hot+logscale/5+商品尺寸|12|scale只用第0—119天|
|6个已完成供应商提前期+均值/标准差/最小/最大/中位/近期差|12|离线读取t−10..t−5；现场t−14..t−9|
|需求统计：均值/标准差/分位数/零比例/趋势及7/14/28天汇总|22|由同一历史窗口构造|
|review/10、净库存或库存位置/scale|2|实际决策时每种策略使用自己的库存|

此外每个预测原点有H=20天已知未来促销/日历sin/cos，60维；训练3个fork各自对齐，不声称它们包含在上述132维私有定义内。库存只在融合的最后隐藏层加入，review进入融合层。VLT网络另加静态特征，第一层输入24维。

## 训练样本

`training_samples.npz`含seq[M,28,3]、static[M,12]、vl[M,12]、stats[M,22]、known[M,3,20,3]、stock/review[M]、sid/day/split、I/scale、L/Lnext/R、actual_future[M,20]、fork_y[M,3,20]、label[M]。

`L`、`Lnext`、`actual_future`、`fork_y`、`label`均为**标签或评估信息**，不在模型输入INPUTS列表中。训练库存来自因果Normal行为策略，并添加独立于未来的随机库存状态增强；不是利用未来最优策略产生的在线状态。

训练决策日180..260且完整未来窗口不越过279；验证决策日280..310且不越过329；两者之间清除未成熟样本。各商品review决定实际样本日，train每个历史状态另加一个随机库存增强；val不增强。数据量分析按唯一训练商品抽取20%—100%，固定所有验证/测试商品，检验跨同一总体下的样本量影响，不是未见商品外推实验。

## 结果字段

- `holding_cost`、`stockout_cost`、`total_cost`：离线为完整30天每商品成本和，再跨商品平均；现场主表同为每商品30天成本和，**未缩放为原文日均费用**。
- `turnover_days`：平均正库存/平均日需求，单位天。积欠不抵减正库存；与作者notebook可能负值的口径不同。
- `stockout_ratio`：发生积欠或丢失需求的天数/观察天数；不是缺货数量/需求数量。
- `relative_gap_pct`：相对同路径OPT总成本的增幅百分数。
- `lost_units`：混合规则中累计丢失需求；离线backorder规则为0。
- `net_stock_at_order`、`inventory_position`：前者净库存，后者加尚未到货订单；现场使用后者作为网络库存输入，这是工程扩展。
- `p_clustered`：按原商品ID聚类的p值；`p_welch_descriptive`仅作两组描述比较，重复匹配时不作为主推断。

现场匹配允许重复对照；`cluster_id`始终是原始series_id，不能以匹配行号替代。合成处理效果由相同初始状态和需求路径下各策略实际滚动生成，没有预填成本下降百分数。
